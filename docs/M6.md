# M6: the scripted joint check

The check from `docs/PLAN-IDENTITY-UI-FIRST.md` (M6): sign in on the CLI, create and publish a record, edit it in the UI as the same account, import the edit as a new local version, sign out. `scripts/m6.sh` runs it; the driver is `TestM6Joint` in `cmd/provenance/m6_joint_test.go`, behind the `m6` build tag so `go test ./...` never runs it.

**It publishes a record to the account you use.** Everything on AT Proto is public: use a throwaway account, and expect a `M6 joint check <time>` record left behind. There is no delete endpoint.

## What it checks

1. CLI: `login --no-browser`, approval, `whoami` returns the account.
2. CLI: a temp git project gets a new blueprint, opened, and `publish --yes` writes version 1; a second publish writes nothing.
3. UI: the edit is made as the same account (below).
4. CLI: `import --all` brings the edit in as version 2 with the UI account as author; `history` and the record file show it; a second import imports nothing.
5. CLI: `logout`, then the old refresh token is refused (401).
6. No token reached any output.

## Local variant (loopback backend, real UI, Cypress)

Needs provisio-backend's dev server (`PORT=3100 node test/dev/local-server.ts`, fake PDS, `/dev/approve` and `/dev/login`) and a UI checkout with `npm ci` done:

    M6_UI_REPO=/path/to/linespec-provenance-ui scripts/m6.sh

`m6.sh` starts the UI dev server (`VITE_AUTH_MODE=provisio`, 127.0.0.1:5173), sets `M6_APPROVE_URL=$PROVISIO_AUTH_URL/dev/approve`, and sets `M6_UI_CMD` to run the UI repo's `cypress/e2e/provisio-m6-edit.cy.ts` under `xvfb-run`. The spec signs in as the default dev account through `/dev/login`, opens `/records/$ID`, edits intent and reason, and asserts through the API that the head moved from N to N+1 with origin `ui`. The driver passes it `CYPRESS_M6_RECORD_ID`, `CYPRESS_M6_HANDLE`, `CYPRESS_M6_SERVICE_URL`, `CYPRESS_M6_NEW_INTENT` and `CYPRESS_M6_REASON`.

Without `M6_UI_REPO` and `M6_UI_CMD` the driver does the UI step itself over the API and says so: that run proves the CLI half and the wire contract, not the UI.

## Real-service run (Caleb)

    PROVISIO_AUTH_URL=https://auth.provisio.dev PROVISIO_API_URL=https://api.provisio.dev/v1 \
    M6_UI_CMD='…' scripts/m6.sh

With `M6_APPROVE_URL` unset the test prints the verification URL and user code and waits up to 11 minutes: approve it in a browser as the throwaway Bluesky account. The UI step is the same edit made by hand in the deployed UI (`M6_UI_CMD` can be a small script that waits for you), or the Cypress spec if the deployed service has a test sign-in (it does not; `/dev/login` exists only on the local server).

## Environment

| Variable | Meaning |
| --- | --- |
| `PROVISIO_AUTH_URL`, `PROVISIO_API_URL` | the backend (default: loopback :3100 and `/v1` under it) |
| `M6_APPROVE_URL` | endpoint that approves a device code; set automatically for loopback, unset means a human approves |
| `M6_HANDLE` | handle to approve as (dev server only) |
| `M6_UI_REPO` | UI checkout; `m6.sh` starts Vite and builds `M6_UI_CMD` from it |
| `M6_UI_CMD` | shell command for the UI step; exit 0 means the edit was made |
| `M6_REAL_HOME` | your real home, set by `m6.sh`: the package tests run with a temp HOME, the UI tooling needs the real one |
| `M6_UI_URL` | where the UI dev server listens (default http://127.0.0.1:5173) |
